## Key Findings Summary

### Finding 1: Pageid is Upstream Data
- Generated by **replybot** from Facebook webhook events
- Stored in database when state is updated
- Bail system inherits, never modifies

### Finding 2: No Selection Logic
- SQL: `SELECT ... s.userid, s.pageid ...`
- Returns **all** pageids for matching users
- No filtering, no defaults, no selection

### Finding 3: Type Safety
- 7 validation checkpoints throughout stack
- NO silent defaults anywhere
- Errors thrown or rows skipped if validation fails

### Finding 4: Multi-Platform by Design
- Composite key: `(userid, pageid)`
- One user can have multiple pageids
- Each combination independent
- All combinations bailed correctly

### Finding 5: Strong Upstream Validation
- `getPageFromEvent()` throws if pageid missing
- Prevents invalid states from being created
- Bail system only receives valid states
